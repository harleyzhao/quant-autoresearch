# 方案：面向电影与游戏的 Web 端程序化植物生成器（工作代号 Arbor）

> 日期：2026-09。前置阅读：`01-调研-SpeedTree与学术前沿.md`。
> 本文是技术与产品方案，不含代码。所有「阶段」时间按 4–6 人核心团队估算。

---

## 0. 一句话定位

**把树当作「生长了 N 年、处在某个季节、站在某个环境里的生物」来生成，而不是当作「一组按曲线摆放的圆管」。** 输出面向 UE / Unity / Houdini / USD 管线，在浏览器里建模、协作与预览。

要在四个维度同时超过 SpeedTree，且每一项都有 2022–2025 的论文或工业实现背书：

| 维度 | SpeedTree 10 | 本方案 | 依据 |
|---|---|---|---|
| 结构真实感 | Generator 层级 + 手调曲线 | **自组织生长模拟**（芽竞争光/空间、顶端优势、向重/向光性、资源分配）+ 神经先验 | Pałubicki 2009；DeepTree 2023；Autoregressive Trees 2025 |
| 近景几何 | Lofted 圆管 + 靴口贴图 | **Strand 束体积模型**：非圆截面、真实分叉融合、树皮纵脊、断枝断口 | Interactive Invigoration 2024；Stressful Tree 2025 |
| 时间轴 | 季节滑条（贴图切换） | **年龄 × 物候 × 风** 三条时间轴，同一株可输出任意年份/任意物候日/任意风况 | Ecoclimates 2022；Autoregressive 4D；DynamicTree 2025 |
| 材质 | 贴图库订阅 | **程序化材质图**（树皮/叶/苔藓/地衣），参数随直径、年龄、湿度、季节连续变化；可由参考图反推 | VLMaterial / MultiMat / ProcTex 2025 |
| 可控性 | 曲线 + 手绘 + mesh force | 轮廓/体积包络、环境障碍、参考图/草图、文字描述四种输入统一为**生长场** | Tree-D Fusion 2024 |
| 平台 | 桌面单机、按机器授权 | Web（three.js WebGPU）+ 桌面壳，URL 分享、版本、云端重算 | WebGPU 全浏览器 baseline |

## 1. 产品边界

### 1.1 做什么

1. **树木与灌木**为第一优先（乔木、灌木、藤本），草本/花卉第二阶段，草地/苔藓面片第三阶段。
2. **两条输出线**：
   - 游戏线：分级 LOD 网格、部件实例化（对齐 Nanite Assemblies 思路）、风数据、impostor、图集。
   - 电影线：高密度 strand 蒙皮网格或 USD 曲线（Houdini/Katana 侧再细分）、4K–8K 材质、生长/风 Alembic 缓存。
3. **用户角色**：环境美术（游戏）、素材/植被 TD（电影）、独立开发者与虚拟制作团队。

### 1.2 不做什么（至少 V1 不做）

- 不替代引擎渲染器：Web 端预览目标是「拍板级」而非「最终画质」。
- 不做整片森林的生态摆放（PCG / Houdini 已很成熟），只提供**种群变体生成**与导出。
- 不做通用 DCC 建模。

## 2. 核心表示（数据模型）

所有模块围绕一个可序列化、确定性（同 seed 同结果）的中间表示 **PlantGraph**：

```
Species (物种定义, JSON)
 ├─ growth: 芽/枝生长规则参数（见 §3）
 ├─ organs: 叶/花/果/刺/皮的形态与材质引用
 ├─ phenology: 物候曲线（按积温或日历日）
 └─ material graphs: 树皮 / 叶片 / 附生物 节点图

Individual (个体 = Species + seed + environment + age + date + health)
 └─ Skeleton  — 有向树图；每个节点：位置、方向、年龄(出生年)、分枝阶、
                strand 计数、活/死、芽类型；每条边：长度、锥度、扭转
     ├─ StrandBundle — 每段的 strand id 集合 → 截面轮廓(多边形) 
     ├─ Organs — 叶/花/果实例：父节点、局部变换、生长阶段、损伤
     └─ Derived caches: 蒙皮网格、LOD 链、风层级、impostor、贴图
```

设计要点：
- **Skeleton 与 Strand 分离**：Skeleton 决定「有哪些枝」，Strand 决定「枝有多粗、什么截面」。可以只用 Skeleton 跑轻量模式（游戏批量变体），也可以开 Strand 做电影近景。
- **年龄写进节点**：任意年份的形态 = 过滤「出生年 ≤ t」的节点并按该年 strand 计数重算粗细，这就是「同株时间轴」的来源。
- **物候写进器官**：叶实例带「展开度、叶绿素、类胡萝卜素/花青素、含水量、离层进度」五个标量，材质图读取它们，季节不再是贴图切换。
- **环境写进个体**：光照体素、障碍 SDF、风向、坡度、邻株遮挡，全部是生长场输入，改环境即重长。

## 3. 生长引擎（结构真实感的来源）

### 3.1 基线：自组织生长（V1 必做）

按 Pałubicki 2009 + 空间殖民实现，每「年」一个大步、每年若干小步：

1. **环境感知**：树冠占据体素场（32³–128³ 自适应），每个芽计算可得光 Q（阴影传播）与可用空间（殖民点密度）。
2. **资源分配**：Borchert–Honda 式：根部资源 v 按 λ 权重在主/侧芽间分配，λ 即顶端优势。
3. **芽命运**：休眠 / 抽枝 / 成花 / 死亡，由 Q、v、年龄、物种参数决定。
4. **新梢方向**：默认方向 + 向光（殖民点均值）+ 向重/向上 + 随机扰动 + **用户生长场**（§5）。
5. **次级生长**：管道模型，strand 计数向下累加 → 半径；达芬奇指数可调（默认 2，物种覆盖）。
6. **枯死与脱落**：Q 低于阈值连续 k 年 → 枝死 → 保留枯枝或脱落（留下断口/树瘤，见 §4）。

参数量控制在 **30–40 个物种级参数**，全部有植物学意义（可被文字/图像反推），SpeedTree 的几百条曲线中大部分成为**涌现**结果。

### 3.2 神经先验（V2）

- **物种先验**：在自组织引擎上采样 10⁵ 级树，训练 Autoregressive Trees 风格的圆柱 token 模型（沙漏 Transformer）。用途：(a) 秒级出「初稿」，再用生长引擎「续长」；(b) 图像/草图/点云条件生成；(c) 树冠补全。
- **参数反推**：给定参考图 → 分割树冠/主干 → 优化 30–40 个物种参数使渲染剪影/分枝统计匹配（可微剪影 + 统计损失），路线同 Tree-D Fusion 的「包络 + 条件化殖民」，但保留完整可编辑参数。
- **数据合规**：训练数据来自自研引擎合成 + Tree-D Fusion（开源）+ 自采 LiDAR/扫描，不依赖竞品资产。

### 3.3 藤蔓、根系、共生

- 藤蔓：同一引擎加「攀附」项（与障碍 SDF 的法向吸附 + 重力悬垂），对齐 SpeedTree 10 的 Vine。
- 露出地表根系：向下的自组织生长（避开石块 SDF），电影近景常用。
- 附生物（苔藓、地衣、真菌）：按湿度/朝向/年龄在树皮材质图里生成，不做几何（V1）。

## 4. Strand 体积模型（近景真实感）

实现 Interactive Invigoration 的工程简化版：

1. 每个末端芽发出一根 strand，沿父链向根累加；每段 strand 集合决定截面。
2. 截面生成：把该段 strand 在垂直于枝轴的平面上做**松弛堆积**（圆盘填充 + 少量迭代），取外轮廓 → 多边形（16–64 边）；分叉处两束分开，自然形成 Y 形融合与「树领」。
3. 蒙皮：沿骨架扫掠多边形截面并在分叉处做布尔式缝合（或 SDF 联合后网格化，电影线用后者）。
4. 树皮位移：截面外轮廓的凹凸 + 材质图的高度 → 位移贴图/曲面细分，纵向脊纹自然沿 strand 走向。
5. 死枝与断口：删除 strand 子集但保留其在父段的截面痕迹 → 树瘤、断口、愈伤组织；V2 接入 Stressful Tree 的弯折/断裂。

性能预算：Web 端 1e4 strand、1e3 段在 Worker 内 < 1 s 更新；电影线离线可到 1e5。

## 5. 形状与环境控制（可控性）

四种输入统一为一个 **生长场**（3D 向量场 + 标量增益 + 障碍 SDF）：

| 输入 | 转换 | 典型用途 |
|---|---|---|
| 体积包络（画/拉/导入网格） | 包络内殖民点密度高、外部为 0 | 「树冠要这个形状」，行道树修剪形 |
| 障碍与邻株（导入场景网格/其他个体） | SDF 排斥 + 遮光 | 贴墙生长、林下树、避让建筑 |
| 笔刷（增长/抑制/朝向/剪除） | 局部改增益或方向 | 对齐 SpeedTree Freehand + Trim，但改笔刷即重长而非手改几何 |
| 参考图 / 草图 / 文字 | §3.2 反推物种参数 + 包络 | 「像这张照片的老橡树」「东北红松，30 年，偏斜」 |

关键体验：**所有控制都是非破坏的**，改任意输入后从缓存年份增量重长（每年一层缓存），交互延迟目标 < 200 ms（轻量模式）。

## 6. 叶片、花果与物候（季节）

### 6.1 叶片形态

- 叶形：轮廓样条 + Runions 2005 脉络生长 → 叶片网格（3–50 三角）、脉络掩码、厚度图。
- 叶序/着生：由物种参数（互生/对生/轮生、叶柄角、叶倾角分布）在生长时决定，非后期散布。
- 叶片形变：含水量降低 → 沿脉络卷曲（双层网格 + 收缩），秋季/干旱直接可见。

### 6.2 物候模型（V1 必做）

按物候学的**积温（GDD）+ 光周期**驱动一年内 6 个阶段：休眠 → 芽萌 → 展叶 → 成熟 → 衰老（叶绿素降解、花青素合成）→ 离层脱落。用户暴露：日期滑条 / 「季节预设」/ 直接调各阶段的进度。

- 叶色不是贴图切换，而是材质图里 **叶绿素/类胡萝卜素/花青素/褐变 四通道混色**，随每片叶的阶段与所处光照（阳面先红）变化，同一树冠内自然有梯度。
- 落叶顺序由每片叶的阶段 + 风暴露决定；地面落叶层可选导出。
- 花期/果期同法；针叶树用「针叶年龄层」替代落叶。

### 6.3 材质（叶）

双面 BSDF：正面反射 + 背面透射（BTDF）+ 薄层次表面近似（Habel 2007 简化），透射颜色由叶绿素通道驱动；Web 端用 three.js TSL 实现，导出时映射到 UE Two-Sided Foliage / glTF `KHR_materials_transmission` + 自定义扩展。

## 7. 程序化材质系统（树皮等）

- 节点图 DSL（JSON），节点类型对齐 Substance 常用子集（噪声、Voronoi、扭曲、坡度/曲率输入、混合、高度→法线），在 **WebGPU compute** 中评估到贴图。
- **结构输入**：材质图能读到几何侧信息：局部直径、枝龄、朝向（北面苔藓）、离地高度、strand 密度。这是「树皮随年龄从光滑到龟裂」的实现方式。
- 图像反推：VLMaterial / MultiMat 路线，用视觉语言模型给出初始节点图与参数，再做可微优化对齐参考图（V2）。
- 输出：4K/8K PBR 集（BaseColor/Normal/Roughness/Height/AO/Transmission/SSS），KTX2 压缩供 Web 与引擎。
- 起步资产：自建 20 种树皮 + 30 种叶片材质图作为种子库，全部程序化，无外部授权依赖。

## 8. 风与动画

生成时即有层级骨架，因此一次生成、三种导出：

| 表示 | 用途 | 说明 |
|---|---|---|
| 层级顶点风（Pivot Painter 2.0 兼容贴图 + 顶点色） | UE/Unity 通用 | 深度 0–3 层枢轴、长度、频率；直接对标 SpeedTree Wind |
| 骨骼蒙皮 | Nanite Skinning / 过场 | 每级主枝一根骨，叶用顶点风 |
| 模态频谱（DynamicTree 思路） | 电影、高保真 | 从 strand 刚度求前 k 阶模态，运行时叠加 |

Web 预览用 TSL 顶点风，参数与导出一致。

## 9. 渲染与 LOD（Web 端）

- three.js **WebGPURenderer**（r171+ 生产可用），WebGL2 自动回退用于预览低配。
- 叶：实例化叶卡或真实叶片网格（近景），`BatchedMesh` + GPU 剔除。
- LOD 链：LOD0 全几何 → LOD1 简化（meshoptimizer wasm）→ LOD2 枝簇卡片 → 八面体 impostor（Worker 离线烘焙）。
- 部件实例化导出：把重复枝簇/叶簇识别为「部件」，导出为 glTF `EXT_mesh_gpu_instancing`，与 Nanite Assemblies 概念对齐，磁盘与显存下降一个数量级。
- 阴影/GI 预览：级联阴影 + 简单 SH 环境；不追求电影级 GI。

## 11. 系统架构

```
┌──────────── Browser (three.js WebGPU) ────────────┐
│ UI: 参数面板 / 节点图 / 时间轴 / 笔刷 / 场景视口      │
│ Render: TSL 材质、BatchedMesh、LOD、impostor       │
│ Worker pool:                                       │
│   ├─ Growth kernel (Rust→WASM, 确定性)             │
│   ├─ Strand & skinning (WASM)                      │
│   ├─ Material graph eval (WebGPU compute)          │
│   └─ Impostor bake / meshopt                       │
└───────────────────────┬───────────────────────────┘
                        │ .arbor JSON, 资产
┌───────────────────────┴───────────────────────────┐
│ Cloud (可选)                                       │
│  ├─ 高算力重算：电影级 strand、8K 材质、USD/FBX 写出 │
│  ├─ 神经服务：图像→参数、文字→物种、先验采样        │
│  ├─ 协作：项目/版本/分享链接/评论                   │
│  └─ 物种库：官方 + 社区 Species                     │
└───────────────────────────────────────────────────┘
桌面壳：Tauri 打包同一前端，提供本地文件系统、离线、离线许可。
```

技术选型理由：
- **Rust → WASM** 做生长与 strand：确定性、无 GC 抖动、同一份代码可在云端原生运行。
- **three.js + TSL**：跨 WebGPU/WebGL2 一套材质代码；社区 impostor / BatchedMesh 生态成熟。
- **Tauri**：电影客户不接受纯网页时给桌面版，成本远低于双端。
- 神经模型放云端而非浏览器：Transformer 先验用 WebGPU 推理可行但首包大，V2 再评估端侧。

## 12. 参数体系（面向用户）

三层暴露，避免 SpeedTree 的「几百条曲线」：

1. **意图层**（任何人）：物种、年龄、季节日期、健康度、风况、树冠形状预设、环境（孤植/林下/临街/临墙）。
2. **植物学层**（美术/TD）：顶端优势、分枝角分布、向光/向重强度、节间长、叶序、达芬奇指数、芽存活率、枯枝保留率、树皮龟裂起始直径、物候阈值……约 40 项。
3. **覆盖层**（专家）：笔刷、包络、逐枝锁定、材质节点图、导出细节。

每一层的改动都可回放、可版本化，且**所有层共享同一个 seed**，同一株可无限产出「同物种不同个体」。

---

## 13. 真实感度量（防止自嗨）

- 结构统计对照 LiDAR/开源数据（Tree-D Fusion、公开林业点云）：分枝角分布、达芬奇指数、枝长–直径异速关系、叶面积指数。
- 图像层面：对同物种真实照片的剪影/FFT 纹理统计距离；周期性盲评（美术 A/B 对 SpeedTree/Megaplants/照片）。
- 每个物种发布前必须过统计门槛 + 盲评门槛。

## 15. 主要风险与对策

| 风险 | 对策 |
|---|---|
| UE PVE 免费且渲染最强，吞掉游戏侧 | 不比渲染比**数据**：把更好的骨架/部件/材质导给 PVE；主攻跨引擎、电影、时间轴、协作 |
| Web 内存/性能上限（电影级 strand、8K 材质） | 分层：浏览器做轻量 + 预览，云/桌面做重算；.arbor 只有 KB 级，重资产按需生成 |

## 16. P0 第一批技术 spike（建议立即开始）

1. Rust 自组织生长内核（Pałubicki 2009 全流程）+ WASM 绑定，含年份缓存与增量重长。
2. strand 截面松弛堆积 → 多边形 → 分叉缝合蒙皮；输出与圆管方案对比图。
3. three.js TSL 双面叶 BSDF + 层级顶点风；BatchedMesh 5e4 叶实例 60 fps。
4. WebGPU compute 评估一个 12 节点的树皮材质图到 2K，含「直径→龟裂」输入。
5. glTF 导出 + `EXT_mesh_gpu_instancing` 部件表 → UE 5.7 / Unity 6 导入验证。
6. 物候曲线驱动叶色四通道混色，做「同一株 365 天」的连续序列。

每个 spike 一周到两周，结论决定 P1 的技术锁定。
